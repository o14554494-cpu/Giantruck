# 视觉、控制与路径规划联调说明

> V2 配套说明：本工程对应包内 `OpenMV/visual.py`。新版视觉增加固定曝光、黄色平均 LAB 纯度校验和跨颜色互斥；控制端增加观测范围过滤、弱目标二次确认、末端位置关联门限、空路线补扫和视觉链路状态字段。串口数据格式保持不变。

## 1. 系统当前结构

系统采用“首次扫描 + 视觉持续更新 + 小批量规划 + 每次拾取后重规划”的滚动规划方式。

```text
OpenMV 图像
  -> 红/黄多目标检测
  -> 相机相对坐标估计
  -> UART 带校验帧
  -> STM32 全局目标地图
  -> 贪心初始路径 + 2-opt 路径改进
  -> 导航/视觉末端对准状态机
  -> 左右轮 PWM
  -> 编码器里程计反馈到地图和规划器
```

视觉板只负责“看见什么、物块相对车在哪里”；控制板负责“车在哪里、先捡哪个、怎样运动”。这样可以避免视觉板与底盘控制各自维护一套互相矛盾的决策状态。

## 2. 硬件连接

| 信号 | OpenMV | STM32F103VET6 |
|---|---|---|
| 视觉数据发送 | P4 / UART3_TX | PC11 / UART4_RX |
| 模式命令接收 | P5 / UART3_RX | PC10 / UART4_TX |
| 参考地 | GND | GND |
| 串口参数 | 115200, 8N1 | 115200, 8N1 |

必须共地，UART 信号使用 3.3 V 电平。UART4 已配置接收中断，优先级低于 10 ms 电机控制定时器。

## 3. 模块输入与输出

| 模块 | 输入 | 输出 | 主要文件 |
|---|---|---|---|
| OpenMV 采图与检测 | RGB565、QVGA 相机图像；STM32 模式命令 | 红/黄物块列表：颜色、左右偏移、前向距离、质量、像素面积 | `visual.py` |
| UART 视觉协议 | UART4 接收字节流 | 完整且通过异或校验的 `VisionFrame_t` | `vision_protocol.c/.h` |
| 坐标转换与目标地图 | 视觉相对坐标、编码器里程计位姿、时间戳 | 去重后的全局物块：ID、颜色、X/Y、质量、观测次数、是否已收集 | `main.c`、`target_map.c/.h` |
| 路径规划 | 当前位姿、最多 16 个可用目标 | 最多 8 个目标 ID 的短期访问顺序及估计代价 | `path_planner.c/.h` |
| 自动状态机 | 当前路径、目标地图、实时视觉、编码器位姿 | 左右轮目标速度、视觉扫描/跟踪模式、地图状态更新 | `main.c` |
| 电机与里程计 | 左右轮目标速度、TIM4/TIM5 编码器计数 | TIM3 双路 PWM、机器人 X/Y/航向、左右轮 RPM | `main.c` |

坐标约定：

- OpenMV 输出 `lateral_mm`：向车体右侧为正；`forward_mm`：车体前方为正。
- STM32 全局地图：X 轴为启动方向，Y 轴向左，航向角逆时针为正。
- 所有距离单位均为毫米，角度在程序内部使用弧度。

## 4. 串口协议

每个数据包格式为 `$有效载荷*CS\r\n`，`CS` 是有效载荷所有 ASCII 字节的异或校验，两位十六进制。

OpenMV 每 200 ms 发送一个完整目标帧：

```text
$F,序号,目标数*CS
$T,序号,索引,颜色,右偏毫米,前向毫米,质量,像素数*CS
...每个目标一条 T...
$E,序号*CS
```

颜色：`1=红色`，`2=黄色`。只有序号一致、数量一致且校验正确的完整帧才会进入目标地图。

STM32 发给 OpenMV 的模式命令：

| 命令载荷 | 作用 |
|---|---|
| `C,S,0` | 扫描红色和黄色全部目标 |
| `C,T,1` | 末端接近时只跟踪红色 |
| `C,T,2` | 末端接近时只跟踪黄色 |
| `C,P,0` | 暂停发送目标帧 |

## 5. 路径优化原理

规划器不是只选欧氏距离最近的一个目标。每个候选目标的初始选择代价为：

```text
代价 = 行驶距离 + 260 × 转向代价 + 2 × (100 - 视觉质量)
```

其中转向代价根据当前航向与目标方向的夹角近似计算，因此会优先选择少调头、质量较高的目标。规划步骤为：

1. 从当前位姿出发，用带转向和质量惩罚的贪心法生成最多 8 个目标的初始顺序。
2. 用最多 4 轮 2-opt 交换反转路径片段；只有总成本下降才保留。
3. 行驶中视觉继续更新目标地图。距离目标较远且地图发生变化时，最短每 700 ms 滚动重规划。
4. 进入目标 220 mm 范围后锁定颜色，改用实时图像坐标末端对准，避免完全依赖累计里程计。
5. 完成一次收集动作后将目标暂时标记为已收集，并立刻规划下一批。

这不是包含障碍物的 A* 路径规划。目前场地被假定为可通行平面，优化的是物块访问顺序和转向次数。

## 6. 自动运行状态

| 状态 | 行为 | 转移条件 |
|---|---|---|
| `SCAN` | 原地旋转，视觉扫描并建图 | 接近一圈或 8 秒 |
| `PLAN` | 生成并改进短期目标顺序 | 有目标进入 `NAVIGATE`，无目标进入 `COMPLETE` |
| `NAVIGATE` | 用地图目标与编码器位姿导航，同时滚动重规划 | 距目标小于 220 mm |
| `ALIGN` | OpenMV 只跟踪当前颜色，视觉闭环居中 | 距离小于 105 mm 且横向误差小于 25 mm |
| `COLLECT` | 低速直行 900 ms | 计时结束，标记目标并重规划 |
| `RECOVER` | 目标丢失时旋转搜索 900 ms | 返回规划 |
| `COMPLETE` | 停车并继续扫描 | 手动重新启动或复位 |

## 7. 调试命令

UART4 单字节命令：

| 命令 | 功能 |
|---|---|
| `A` | 清空旧地图并启动自动扫描/规划/收集 |
| `X` | 停止自动模式并清空地图 |
| `M` | 打印目标地图 |
| `P` | 打印当前规划顺序与估计成本 |
| `V` | 打印轮速、PWM、PID、自动状态、位姿、地图数量和协议错误数 |
| `F/B/L/R/S` | 退出自动模式并手动前进/后退/左转/右转/停止 |
| `0`～`9` | 手动速度设为 0%～90% |

正式连接 OpenMV 时 UART4 已被视觉链路占用；若需同时查看调试文本，应增加另一路串口或使用 SWO，而不是把 USB 串口模块并联驱动在同一 RX 线上。

## 8. 上车前必须标定

以下宏或常量目前是起始值，不能直接视为实车最终参数：

| 参数 | 当前值 | 标定方法 |
|---|---:|---|
| `CAMERA_FOCAL_LENGTH_PX` | 225 px | 把已知宽度物块放在已知距离，按 `焦距=像素宽×距离/物块宽` 计算 |
| `RED/YELLOW_OBJECT_WIDTH_MM` | 25 mm | 用实际物块宽度替换 |
| OpenMV 红/黄阈值 | 代码内默认值 | 在比赛光照下用 Threshold Editor 调整 |
| `ENCODER_COUNTS_PER_WHEEL_REV` | 1560 | 实测车轮一圈的四倍频计数 |
| `WHEEL_DIAMETER_MM` | 80 mm | 测量有效滚动直径 |
| `WHEEL_TRACK_MM` | 184 mm | 原地转一圈反算更准确 |
| 左右编码器符号 | 均为 `+1` | 正向行驶时两侧里程必须都增加 |

建议先悬空验证方向，再低速落地验证直行距离和原地转角，最后才测试自动收集。

## 9. 当前边界

- 已实现目标检测、通信校验、建图、访问顺序优化、里程计导航、近距离视觉对准和失目标恢复。
- 当前“拾取成功”依据 900 ms 直行动作推定，没有接入滚轮电机、光电门、仓内传感器或电流反馈。因此它能完成导航到物块并执行收集动作，但不能硬件确认物块已经入仓。
- 目前未检测墙体、车辆或动态障碍物；没有占据栅格和 A* 绕障。
- 红黄同色且距离很近的物块可能因视觉轮廓粘连而被识别成一个，需要结合实物尺寸、安装高度和阈值调试。
- PID 默认仍关闭；编码器测速和里程计已运行。确认两侧编码器与参数无误后，再按 `ENCODER_PID_GUIDE.md` 开启闭环。
