# Greedy IMU 航向融合说明

固件标记：`FW=v6.1+GREEDY_START_UR`（继承本说明中的IMU功能）。

## IMU 在 Q 模式中的职责

JY901S 的新鲜 YAW 数据现已接入 Q/Greedy：

1. 60°分段扫描优先用 IMU 航向差决定何时停车。
2. IMU 航向以 0.65 的比例周期修正编码器航向，Coverage 使用修正后的车体方向。
3. 右上卸货前的调头使用同一融合航向判断是否对准。
4. 编码器继续计算前进距离、场地 `(x,y)` 和两个 IMU 帧之间的短时转角。
5. 超过 500 ms 没有新鲜角度帧，自动退回编码器转角，不继续使用旧 IMU 数据。

OpenMV 仍负责物块左右偏差和近距离对准；IMU不会识别物块，也不能确认物块是否真正入仓。IMU只能减小航向漂移，不能修复轮子打滑造成的行驶距离误差或给出绝对场地坐标。

## 上车前必须确认正负方向

代码坐标规定逆时针转向为正，默认：

```c
#define IMU_NAV_YAW_SIGN 1.0f
```

先发送 `I` 建立零点，然后手动把车逆时针转约 90°。如果蓝牙的 `REL_YAW` 约为 `+90°`，保持 `+1.0f`；如果约为 `-90°`，将 `Core/Inc/imu_navigation.h` 中该宏改为 `-1.0f`，重新编译烧录。方向错误时 Q 的左负右正扫描会因 IMU角度朝相反方向变化而在 3秒后报扫描超时，这是保护表现。

## 蓝牙判断是否正在使用 IMU

发送 `Q` 后应看到：

```text
IMU NAV: 60DEG SCAN + COVERAGE HEADING + UNLOAD ALIGN; ENCODER FALLBACK
```

发送 `V`：

- `IMU_NAV=OK`、Greedy行中的 `NAV=IMU`：正在使用新鲜IMU航向。
- `IMU_NAV=WAIT`：Q开始后还没有取得有效角度帧。
- `IMU_NAV=STALE` 或 `NAV=ENC`：超过500ms没有新角度，已经降级为编码器。
- `REJECT` 增加：相邻有效帧跳变超过45°，本次跳变被拒绝并安全重新锚定。

`I`是停车IMU诊断模式，`V`立即查询，`S`退出。应先通过I模式确认 `IMU OK`、ANGLE持续增加、AGE较小，再测试Q。`D`直接执行RETURN、Coverage和卸货全链路。

## 推荐实车测试

1. 车轮架空，发送D验证数据和正负方向。
2. 落地清空周围物块，发送Q，只测试一次60°转向；状态应显示NAV=IMU。
3. 观察实际转角。如果方向相反，修改SIGN；如果明显过冲，先降低Greedy扫描速度，不要增大融合比例。
4. 再测试Coverage直线和四个拐角。
5. 最后测试右上调头和后向超声卸货，并随时准备发送S。

本版已通过JY901解析、跨±180°、过期降级、60° IMU扫描、融合航向及原有控制回归。尚未进行ARM链接、烧录和实车标定。
