# v7.3：慢速黑区接近与左墙碰撞恢复

> 本文件记录 v7.3 历史实现。当前工程为 v7.5；卸货前慢速 180° 转向见 `V7.4_CHANGELOG.md`，启动 IMU 零点保存与可靠回正见 `V7.5_CHANGELOG.md`。

## 本版修改

1. 黑色卸货区到达门限从 `50.0%` 降为 `40.0%`：

   ```c
   BLACK_VISION_ARRIVE_X10 400U
   ```

2. 从 IMU 逆时针 90°完成到黑区达到 40% 的行驶速度降低：

   - 沿墙搜索逻辑速度：`18 -> 12`；
   - 黑区视觉接近逻辑速度：`22 -> 16`；
   - 车轮最终 PWM 仍经过最低 60% 的死区补偿，避免低占空比无法启动。

3. 在 `AUTO_UNLOAD_SEARCH_FORWARD` 中加入不依赖视觉墙体识别的左墙碰撞恢复：

   - 前进 400 ms 后才允许检测，避开启动瞬态；
   - 左轮实测速度低于自身目标的 45%，右轮仍达到自身目标的 55%，左右差至少 8 rpm、右轮至少 6 rpm；
   - 同时要求 IMU 航向偏差达到 2.5°，或 Z 轴角速度达到约 20°/s；
   - 条件持续 120 ms 才确认，单次编码器毛刺不会触发；
   - 确认后停车 80 ms、倒退 40 mm、向右修正 10°、前进脱离 100 mm；
   - 最多恢复 5 次，超过后停车并输出故障提示。

4. 修复黑区“连续三帧”的计数方式。现在只在收到新的 `$B` 数据包时累加，主循环不会把同一帧重复计算三次。

## 蓝牙观察

- 启动标记：`FW=v7.3+BLACK3_40+SLOW_APPROACH+LEFT_BUMP_RECOVERY`。
- `V` 和 Greedy 周期状态增加 `BUMP=阶段/次数`。
- 碰撞恢复过程的 `ACTION` 依次为：
  `BUMP_STOP -> BUMP_BACKUP -> BUMP_RIGHT -> BUMP_ESCAPE`。
- 黑区占比达到 40% 且连续收到 3 个新包后输出：
  `BLACK >=40% CONFIRMED`。

## 验证

- 主机协议、IMU、前刷反馈和整车控制回归全部通过。
- 新回归覆盖：编码器与 IMU 联合确认、40 mm 后退、右转 10°、100 mm 脱离，以及 3%/40% 黑区门限。
- 当前环境没有 ARM 交叉编译器，尚未生成/链接 STM32 ELF，也尚未进行实车阈值标定。
