# STM32F103VET6 · 个人赛 v7.6.3

这是 Giantruck 个人技术挑战赛的完整 STM32CubeIDE 源工程。版本重点是“上电自动 Greedy + 双参考 IMU + 严格异常帧过滤 + 黑区视觉卸货”。工程不包含预编译 ELF，需在 STM32CubeIDE 中重新编译后烧录。

## 1. 上电与自动启动

本工程编译宏 `COMPETITION_GREEDY_ONLY=1` 固定为个人赛自动模式：

1. 初始化 STM32 外设、车轮/前刷编码器、UART、JY901S、车尾超声和舵机；
2. 保持车体静止，接收连续 10 帧新鲜且稳定的 JY901S 航向，保存为 `START_RAW`；
3. 初始零点锁定后，前刷启动、Greedy 自动开始，执行 6×60°目标扫描；
4. 后续蓝牙只用于观察和安全停车，不能切换到旧技术赛/对抗赛模式。

若 3 s 内无法完成初始采样，程序停车并报告 `IMU START ZERO TIMEOUT`。此时先检查 JY901S 供电、PA9/PA10 交叉接线、波特率和安装是否稳固，再重新上电。比赛开始前不要移动车体，否则采集到的初始方向不可靠。

## 2. Greedy 收集逻辑

```text
SCAN（6段，每段60°，段末停车观察）
  → 发现目标：锁定一个目标
  → NAVIGATE：按目标横向偏差差速跟随
  → FINAL_ALIGN：低速对准前刷中心
  → COLLECT：达到近距离后按编码器额外前进
  → 停车、刷新短期 IMU → 回到 SCAN
```

- 每一轮只锁定当前目标，收集完成后再重扫，避免动态列表重复加入同一物块。
- 远距离使用视觉横向偏差控制左右轮，目标进入视觉盲区后不会立即判定成功，而是按编码器继续前进额外距离。
- 前刷是独立持续正转执行器；后方舵机不参与收集，仅由卸货状态机调用。
- 代码中保留 `path_planner.c`、`target_map.c` 等通用模块，但本个人赛 Greedy 主流程不使用全局最短路线。

## 3. 双参考 IMU 与严格帧策略

### 初始参考

`START_RAW` 在上电静止阶段采集 10 帧后锁定，整场不会被周期刷新、拾取、解卡或蓝牙操作覆盖。最终黑区返回所需的“回到上电初始方向”均使用它。

### 短期直线参考

`LOCAL_RAW` 只服务于下一段直线/倒车的航向保持：

1. 参考年龄达到 20 s 时先标记到期，不在运动中突然置零；
2. 到下一次安全扫描停车边界后停轮约 300 ms；
3. 接收 6 帧新鲜且相互稳定（约 1.5°以内）的数据；
4. 成功才更新 `LOCAL_RAW` 并清除 PID 历史项，失败则保留旧参考继续运行。

`imu_navigation.c` 还会拒绝过期帧（约 500 ms）、单帧过大跳变（约 25°上限）、异常角速度以及和编码器航向明显不一致的恢复帧；异常恢复需要连续 5 帧一致。这样可以避免一帧串口乱码把航向控制带偏，但不能替代检查磁场干扰、IMU松动或编码器故障。

## 4. 黑区返回与舵机卸货

完整流程由 `main.c` 的 `AUTO_UNLOAD_*` 状态实现：

```text
对齐 START_RAW
  → IMU 闭环逆时针90°
  → 保持航向倒车，车尾超声 ≤180 mm（连续3个新鲜样本）
  → IMU 闭环再逆时针90°
  → 低速直行寻找黑区
      黑色占比 ≥3%且连续3帧：进入黑区跟随
      黑色占比 ≥40%且连续3帧：确认到达
  → 编码器预退80 mm
  → 对齐 START_RAW，逆时针30°
  → 倒车至车尾超声 ≤120 mm、编码器约300 mm或10 s兜底
  → 舵机内转90°、外转180°，车体前后小位移抖动卸货
```

超声安装在车尾，所有卸货距离判断均按“倒车时车尾到墙”的方向解释。卸货结束后不恢复收集，舵机保持安全终点。

## 5. 前刷反馈与自动解卡

进入自动收集后启用刷子反馈；启动宽限后根据脉冲/RPM（以及已配置的电流条件）判断堵转。解卡顺序为“停轮/停刷 → 反转约两圈并后退 → 停顿 → 恢复正转 → 前进约50 mm → 重新扫描”，自动最多 5 次；仍失败进入 `AUTO_UNJAM/JAM_HOLD`，需检查机械和编码器后使用 `K` 恢复。每次解卡结束也会触发短期 IMU 参考刷新。

## 6. 状态与蓝牙

主要自动状态：

| 状态 | 含义 |
| --- | --- |
| `AUTO_IDLE` / `MANUAL` | 待机或安全手动状态 |
| `AUTO_SCAN` | 6×60°扫描 |
| `AUTO_PLAN` / `AUTO_NAVIGATE` | 选定目标并跟随 |
| `AUTO_FINAL_ALIGN` | 近距离低速对准 |
| `AUTO_COLLECT` | 编码器额外前进完成收集 |
| `AUTO_RECOVER` / `AUTO_UNJAM` | 视觉丢失恢复或前刷解卡 |
| `AUTO_UNLOAD_*` | 黑区返回、对准、倒车和卸货子状态 |
| `AUTO_COMPLETE` | 卸货完成/终止等待 |

个人赛编译门控只放行以下命令：

| 命令 | 作用 |
| --- | --- |
| `V` | 输出当前状态、视觉、编码器、IMU双参考、超声和刷子诊断 |
| `S` | 紧急停止车轮并暂停自动 |
| `X` / `0` | 停止并清理当前自动任务 |
| `H` | 停刷并保持故障/HOLD 状态 |

`Q/A/C/D/I/U/G/J/K/P` 以及数字调速等旧命令在此构建中会返回 `COMPETITION GREEDY ONLY: CMD IGNORED`，不会切换模式。上电自动启动无需发送 `Q`。

## 7. 代码结构

| 文件/目录 | 作用 |
| --- | --- |
| `Core/Src/main.c` | HAL 初始化、主循环、状态机、蓝牙分发、黑区卸货流程 |
| `Core/Src/greedy_local.c` | 相机相对单目标锁定和跟随 |
| `Core/Src/greedy_collection.c` | 目标记录、去重和扫描辅助 |
| `Core/Src/imu_navigation.c` / `jy901.c` | IMU 解析、严格帧筛选、航向/PID辅助 |
| `Core/Src/vision_protocol.c` | OpenMV 协议解析及数据新鲜度 |
| `Core/Src/brush_feedback*.c` | 前刷编码器/电流反馈和解卡 |
| `Core/Src/servo.c` | 舱门 PWM 与一次性卸货序列 |
| `OpenMV/` | OpenMV 启动脚本和视觉脚本 |
| `tests/` | 主机端回归测试 |

## 8. 接线与构建

| 模块 | STM32 配置 |
| --- | --- |
| OpenMV | UART4，PC10/PC11，115200 8N1 |
| 蓝牙 | USART3，PB10/PB11，115200 8N1 |
| JY901S | USART1：PA10 接 TX，PA9 接 RX，9600 |
| 车轮/前刷编码器 | 按本目录 `.ioc` 的定时器/EXTI配置接线 |
| 车尾超声、后舱门舵机 | 按本目录 `.ioc` 的 GPIO/PWM配置接线 |

在 STM32CubeIDE 导入本目录 `.project`，执行 `Clean Project` 和 `Build Project`，确认 ELF 来自本目录的 `Debug/` 后通过 ST-Link 烧录。主机测试：

```sh
make -C tests test
```
