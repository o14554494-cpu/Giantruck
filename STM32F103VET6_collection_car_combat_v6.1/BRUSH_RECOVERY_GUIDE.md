# 前刷反转解卡：v6.1 + UNJAM

## 当前能做到什么

蓝牙发送 ASCII `J`（小写也可）触发一次解卡。正常收集仍保持前刷持续正转，后舵机负责卸货。J 是操作者请求，不依赖视觉识别成功；目前没有前刷编码器或电流检测输入，程序不能自动确认堵转，也不能确认一次动作后已经解除堵转。

| 阶段 | 车轮 | 前刷 | 默认结束条件 |
|---|---|---|---|
| STOPPING | 停止 | PWM=0，方向引脚均低 | 150ms |
| REVERSING | 开始后退，达到限制后停车 | 反转，PWM=500/1000 | 2000ms |
| SETTLING | 停止 | PWM=0，方向引脚均低 | 150ms |
| IDLE | 恢复原任务的观测流程；手动模式保持停车 | 正转，PWM=500/1000 | 等待下一次 J |
| HOLD（中断） | 停止 | 停止 | 等待 J 重试或 K 恢复 |

换向前将 PWM 设为 0 并留出停顿，避免在正转驱动下直接切换方向。150ms 是初始值，需按实际机构惯性标定，不能证明刷轴已经完全静止。

反转开始的同时后退，任一轮的编码器累计轮程达到 80mm，或从开始反转起经过 600ms，就先停止两侧车轮。前刷继续完成剩余反转时间。两轮都没有编码器反馈时仍按 600ms 停车；这时不能保证后退距离为 80mm。轮胎打滑、编码器参数误差和控制延迟也会影响真实位移。

## 两圈怎样实现

本版采用定时估算，而非实测圈数闭环：

```text
反转时间(ms) = 60000 × 目标圈数 / 实测反转转速(rpm)
默认占位值：2 圈、60rpm → 2000ms
```

60rpm 是待标定假设，不是电机规格，也不是测量结果。需测量反转 50% PWM 下所要控制的实际输出轴（刷轴）的转速；有减速机构时，不要用电机内部轴转速。负载、电池电压及仍未释放的卡滞都会改变转速，所以定时控制不能保证准确两圈。

若需要精确两圈，需要接入前刷轴编码器/霍尔计数（并考虑传动比），累计到对应脉冲数后停刷，仍保留超时保护。若需要自动触发，需电流或前刷转速反馈，例如“启动宽限期后，正转命令有效且电流持续过高/转速持续过低”；确认模块型号及接线后才能实现具体阈值和驱动。

## 蓝牙操作

| 指令 | 解卡相关行为 |
|---|---|
| J | 启动一次；进行中重复发送不会重新计时；HOLD 中可重新尝试 |
| S / X / 0 | 中断解卡，停轮、停刷，取消原任务自动恢复，进入 HOLD；X 另清空任务记录 |
| K | 仅 HOLD 中可用；再等 150ms 后恢复前刷正转，保持手动停车 |
| V | 显示阶段、刷子方向、左右累计轮程及反转定时参数 |
| A/C/D/F/B/L/R/1～9/G/M/P | 解卡进行中及 HOLD 时暂不执行，并回复 UNJAM BUSY |

普通运行状态下 S/X/0 保持原先的常转规则，只停止车轮；只有中断解卡时会停刷。队列中的 S/X/0 仍优先，例如同一批发送 SJ 会丢弃 J，需等中断回复后再次发送 J。

示例过程消息：

```text
UNJAM START: TIMED BRUSH REVERSE, ENCODER/TIME LIMITED BACKUP
UNJAM REVERSING
UNJAM BACKUP STOP: WHEEL DISTANCE
UNJAM SETTLING
UNJAM CYCLE DONE: BRUSH FORWARD; JAM CLEARANCE NOT SENSED
```

`TIME LIMIT` 代替 `WHEEL DISTANCE` 时，表示后退先达到时间限制，可能轮程尚未到 80mm 或编码器未接好。`CYCLE DONE` 只表示动作完成，不表示传感器确认解卡成功。

V 示例：

```text
UNJAM=REVERSING BRUSH=REVERSE BACK_L=40 BACK_R=39 mm BACK_STOP=0 REV_MS=2000 EST_TURNS=2
```

`BACK_STOP=1` 表示本次后退阶段已结束，`EST_TURNS` 是配置的估算目标圈数，非实际测得圈数。HOLD 及解卡期间暂停多行视觉报告，保持上述状态可查询。

## 和现有任务的配合

- 手动驾驶时 J 正常结束后保持停车，不自动重复之前的 F/B。
- D 模式正常结束后仍为 D，清空旧视觉帧，等待新的有效目标后跟随。
- A/C 正常结束后保留轮式里程计位置、已收集目标和软件载货记录，清除可能被推移的未收集目标并重新扫描。对抗赛计时不清零。
- 不把解卡动作计为一次收集，也不驱动后舵机。带货任务结束准备卸货、正在卸货或执行 G 舵机测试时会拒绝 J；需要中止该动作时先单独发送 S，再发 J。
- 中途 S/X/0 后不会继续原任务。K 恢复前刷后，如需自动驾驶，再发送 A/C/D；这些模式启动命令原有的清空任务行为仍然存在。
- J 是操作者触发的有限后退，可在视觉失联时运行；正常完成后的自动运动必须等新的视觉帧。

## 参数及代码位置

所有参数都在 `Core/Src/main.c` 的用户宏区域：

| 参数 | 默认值 | 作用 |
|---|---:|---|
| COLLECTOR_REVERSE_PWM | 500 | 反转 PWM，满量程 1000 |
| COLLECTOR_REVERSE_TURNS | 2 | 估算目标圈数 |
| COLLECTOR_REVERSE_RPM_ESTIMATE | 60 | 待标定刷轴反转 rpm |
| COLLECTOR_DIRECTION_PAUSE_MS | 150 | 两次换向前的停刷时间 |
| COLLECTOR_BACKUP_DISTANCE_MM | 80 | 任一轮累计轮程限值 |
| COLLECTOR_BACKUP_TIMEOUT_MS | 600 | 后退时间限制 |
| COLLECTOR_BACKUP_PERCENT | 15 | 车轮逻辑后退档位 |

档位 15 经过原有最小 PWM 映射约为 66%，开始时还会使用既有 80% 启动补偿，不能把它理解成 15% 实际占空比。需实测后退位移，必要时降低时间/距离上限。

输入和输出：

- `Motor_ProcessCommand()` 接收 J/K/S/X/0 等命令并处理控制权。
- `CollectorRecovery_Update()` 输入当前毫秒时钟、阶段和累计轮程，输出前刷方向/PWM及左右轮目标；主循环每轮调用，无 HAL_Delay。
- `Robot_UpdateOdometry()` 将左右编码器脉冲换成轮程，调用 `CollectorRecovery_RecordTravel()`。
- `motor3_stop()/motor3_reverse()/motor3_forward()` 操作 PB0/PB1 和 TIM8_CH3（PC8）。
- `Auto_Update()`、`Mission_UpdateIntegration()` 在解卡及 HOLD 时让出控制权。解卡期间不调用原阻塞式超声测距，减少后退停止延迟。

现有超声传感器朝前，后方没有测距输入，因此这个流程不能检测后方墙壁或对手。先在后方留有空间的位置、无物块时验证方向与行程，再用一个容易释放的物块测试；持续卡住时用 S 中断，不要连续反复尝试。

## 构建与验证

使用原 v6.1 工程，Clean/Build 后重新烧录 `collection_car_combat_v6_1.elf`。蓝牙启动标记应为 `FW=v6.1+UNJAM`。相机脚本和硬件接线不需要为手动 J 修改。

宿主测试覆盖实际 C 函数的 PWM 换向顺序、两次停顿、任一轮行程上限、无编码器时间限制、时间回绕、延迟更新、重复命令、所有阶段的 S/X/0、J/K 恢复、A/C/D 恢复、新帧门槛以及卸货/舵机测试互斥。相关 C 文件语法检查通过。未进行 ARM 固件构建或实车试验，实际圈数、距离、释放效果及驱动能力仍需实测。
