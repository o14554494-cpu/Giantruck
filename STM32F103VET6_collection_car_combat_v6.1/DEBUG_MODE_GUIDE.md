# v6.1 视觉蓝牙诊断与直接跟随模式（2026-09-03）

本版提供三个可用蓝牙切换的模式。默认上电是手动待机：前刷常转，车轮等待指令。控制工程目录为 `STM32F103VET6_collection_car_combat_v6.1`，CubeIDE 工程名及 IOC 基名为 `collection_car_combat_v6_1`。当前解卡修订的启动提示含 `FW=v6.1+UNJAM`。解卡流程和中断后的停刷例外见 [BRUSH_RECOVERY_GUIDE.md](BRUSH_RECOVERY_GUIDE.md)。

## 蓝牙指令

使用现有 USART3 蓝牙串口，发送 ASCII 单字符，大小写均可，CR/LF 换行会忽略。

| 指令 | 模式/动作 | 是否规划路线 |
|---|---|---|
| A | 技术赛自动收集，初始扫描、规划、收集和返仓 | 最近邻＋2-opt |
| C | 对抗赛自动收集，单目标滚动选择、分批返仓 | 对抗策略选择目标 |
| D | 调试：直接根据一帧视觉中的一个目标转向和接近 | 不使用地图和路径规划 |
| J | 手动触发前刷反转并短距离后退解卡 | 结束后重新观测 |
| K | 仅在解卡 HOLD 时恢复前刷正转，车轮保持停止 | 无 |
| S | 停止车轮、退出自动/调试，取消卸货与避障动作 | 无 |
| X | 停止并清理地图、任务计数 | 无 |
| V | 输出状态和当前视觉目标详情 | 无 |
| F/B/L/R | 切回手动驾驶 | 沿用手动控制 |
| 0 | 速度清零并退出任务，保持车轮停止 | 无 |

A/C/D 都是重新开始所选模式，会清理上一任务的地图、目标和仓内软件计数，不是无损暂停/恢复。D 会取消旧卸货，后舵机回到原停止位置。通常 S/X/0 不改变前刷常转；在解卡进行中或 HOLD 时，它们同时停轮停刷并取消自动恢复，随后需 J 重试或 K 恢复正转，普通驾驶/模式指令暂被拒绝。J 正常结束会保留原任务的位姿、已收集记录及软件载货计数。

蓝牙接收已从单字节暂存改为 32 字节环形缓冲区（最多存 31 字节），主循环每轮最多消费 4 条指令；S/X/0 优先，清除积压运动指令，等待执行停车期间的新运动指令也会被丢弃。若同一批发送 SD，停车优先，需收到停车反馈后再次发送 D。队列满则计入 BTDROP 并请求停车。

## 怎样查看摄像头有没有识别

目标通知改为蓝牙文本，蜂鸣器保持静音。周期报告默认每 500ms 一次；第一次收到帧、从无目标变为有目标时优先报告；V 可立即查询。最多显示当前帧的 8 个目标，不需要先达到地图确认条件。解卡期间暂停多行视觉报告，V 改回简短的 UNJAM 状态；退出后恢复视觉报告。

例如（数值仅作格式示例）：

```text
VISION OK SEQ=42 RAW=1 MAP=0 AGE=0 RXERR=0 MODE=DEBUG DBG=FOLLOW PICK=0
SEEN I=0 C=1 X=-20 Y=500 Q=30 PX=200 FILTER=DEBUG_BYPASS
```

- RAW：最近有效视觉帧中的原始物块数，来自 OpenMV。
- MAP：控制板地图中可参与正式模式规划的目标数量；调试模式不写地图，通常为 0。
- I/PICK：帧内目标序号/调试模式选中的序号，从 0 开始；PICK=-1 表示没有选中目标。
- C：1=红色，2=黄色。
- X：相机相对横向坐标，毫米；负数左侧，正数右侧。
- Y：相机估计的前方距离，毫米。
- Q：视觉脚本计算的 0～100 质量分，不是神经网络置信概率。
- PX：色块像素数量。
- AGE：距收到该有效帧的毫秒数。
- RXERR：视觉协议解析累计错误数。BTDROP 是蓝牙接收队列满的累计次数，二者不同。
- FILTER：该目标在当前模式中的过滤结果，见下表。

| 输出 | 含义 |
|---|---|
| VISION NO_FRAME | 尚未收到完整、校验通过的视觉帧；检查 OpenMV 运行与 UART4 接线 |
| VISION OK，RAW=0 | 串口有效，摄像头发来零目标帧；应检查视觉端颜色阈值、曝光、视野等 |
| VISION STALE | 曾收到有效帧，但现已超时；不会把缓存目标再次打印为 SEEN |
| FILTER=LOW_Q | 正式模式拒绝 Q<15，但蓝牙仍报告原始观测 |
| FILTER=RANGE | 前方距离不在 60～2500mm 内 |
| FILTER=OUTSIDE | 正式模式按里程计和相机坐标换算后认为目标在场地边界之外 |
| FILTER=OK，MAP=0 | 通过初筛，但可能还没达到地图确认次数，或与已收集目标合并 |
| FILTER=DEBUG_BYPASS | D 模式绕过质量、次数和场地坐标过滤 |

蜂鸣提示原先发生在“可规划目标新增”之后，因此不响不能证明相机没有识别到物块。本版 SEEN 直接暴露收到的目标信息，低质量和场外候选也可查看。

## Q 的计算及原门槛

配套视觉脚本 `calculate_quality` 使用：

```text
fill = min(100, pixels * 100 // (w * h))
size = min(100, pixels // 8)
Q = (3 * fill + 2 * size) // 5
```

例如 fill=80、pixels=200，则 size=25，Q=58。面积小的物块可能得分较低，这不等于“不是物块”。实际摄像头若使用了其他脚本，应以其输出为准。

A/C 仍采用原规则：先通过 Q≥15、距离和场地范围过滤，再要求“累计观测至少两次，或 Q≥75”。75 是单次快速确认的条件，不是所有目标必须达到的门槛；两次观测还需被地图匹配为同一目标。初始扫描时间和场地定位过滤也可能造成“看见了但车不出发”。

D 模式不设 Q 门槛，Q=0 也可跟随；不要求两次确认，不做全局扫描、场地坐标过滤和路径规划。仍要求协议完整、红/黄色类别有效、前方距离在 60～2500mm 内。

## D 模式运动规则

1. 发 D 后停车等第一帧，输出 WAIT_FRAME。
2. 当前帧有多个目标时，选择前向距离最小的一个。每帧重新选择，没有跨帧锁定，所以多目标可能切换。
3. 目标横向偏差明显时先原地向左/右转，DBG=TURN_LEFT/TURN_RIGHT。
4. 基本对准后，根据相对坐标调整左右轮指令并前进，DBG=FOLLOW。
5. 距离≤105mm 且横向偏差≤25mm 时停车，DBG=NEAR。前刷继续转动；调试模式不进行定时冲入、收集计数或自动返仓。
6. 当前有效帧无可用目标时立即停车，DBG=NO_TARGET。
7. 超过 600ms 没有有效帧时停车，DBG=LOST、VHOLD=1；恢复后继续 D 模式，不跳回正式扫描。
8. 前向超声有效距离≤180mm 时停车，DBG=OBSTACLE。此时超声可能看到的是物块本身；调试模式不执行自动后退/转弯避障，也不使用地图墙体判断。

参数位于 main.c 顶部：DEBUG_FORWARD_PERCENT=20、DEBUG_TURN_PERCENT=18、DEBUG_VISION_TIMEOUT_MS=600。百分数参数是车轮逻辑档位，经过原有最低 PWM 映射和 v6 启动补偿后，实际 PWM 会更高。

## 建议测试流程

1. 先上电待机，查看 V：用 NO_FRAME / RAW=0 / SEEN 区分通信、视觉和控制过滤问题。
2. 把一个物块放在相机前方，确认 SEEN 中的 X/Y/Q 随位置变化。
3. 发 D，验证物块左移时左转、右移时右转、居中时前进；移走物块应停车。
4. 发 S 退出调试；再发 A 或 C 可以开始对应比赛模式。观察 MODE、AUTO、DBG、VHOLD 确認当前状态。

源代码没有更改 OpenMV 协议，也没有替换相机中的脚本。若 RAW 始终为 0，降低控制板确认门槛无法创造视觉端未发送的检测结果。

## 验证及边界

原有回归及新增调试测试通过：覆盖真实 C 解析器到蓝牙报告、质量 0 单帧跟随、左右方向、空帧、近距离、超声停车、失联恢复、A/C/D 切换、停止优先和队列溢出停车。前刷常转与后舵机卸货分工保持不变。

测试使用宿主模拟输出，相关 C 源码通过语法检查；尚未进行本版 ARM 构建或实车测试。既有的启动补偿到期更新、超声 DWT 计时等已知问题仍在；本版视觉看门狗依赖主循环正常运行。
