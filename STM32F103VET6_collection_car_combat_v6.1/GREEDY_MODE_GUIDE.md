# Q 最近目标优先自动收集模式

当前固件标记：`FW=v6.1+GREEDY`。新增蓝牙 Q，保留 A 技术赛、C 对抗赛、D 视觉跟随和 G 舱门测试。没有增加引脚，也不要求更换当前配套 OpenMV 脚本或串口协议。

## 运行流程

1. 将小车放在配置的初始位置与朝向，发送一次 `Q`。重置本轮距离列表、已收集位置记录和软件计数，开始旋转搜索。
2. 有完整有效的视觉帧后才允许车轮运动。Q 接受单次红/黄观测，不设置视觉质量下限或二次确认门槛；仍检查协议、60～2500 mm 前向距离及场地边界。
3. 根据小车编码器位姿，将目标相对坐标转换到场地坐标。为目标分配 ID，同色且位置相距不超过 120 mm 的观测更新同一条记录。
4. 根据当前小车位置计算各目标的直线距离，按距离升序维护列表。航向、质量、回仓距离等不参与排序。比较时用距离平方，输出给蓝牙时换算为毫米。
5. 扫描期间一旦有候选就停止旋转，选择最近目标。导航期间持续观察全部颜色，每隔至少 300 ms 可根据新列表重新选择最近目标。
6. 距离目标 220 mm 内进入视觉对准并锁定当前 ID，避免临近拾取时来回切换。视觉仍扫描红/黄两色，新目标继续进入列表，等待下一次选择。
7. 目标前向距离不超过 105 mm 且横向误差不超过 25 mm 时，低速直行 900 ms。动作完整结束才计数一次，并把目标位置标为本轮已收集。
8. 少于 10 次时继续从列表取最近目标。若列表为空，就旋转补扫；扫描角累计达到约 327°或满 12 秒后再次检查列表，仍为空继续补扫，不提前回仓。这里只实现原地旋转补扫，没有额外的跨场地巡逻路径。
9. 计数达到 10 后，进入现有回仓卸货流程：驶向卸货准备点 → 调整朝向 → 倒车 → 舱门舵机卸货 5 秒 → 停车。本版是一轮 10 个，卸货后不自动开始下一轮。

内部复用了 `SCAN / PLAN / NAVIGATE / ALIGN / COLLECT / COMPLETE` 状态名。Q 下 `PLAN` 只取距离列表第一项，不调用 `Planner_BuildRoute()`，不生成多目标路线或计算加权代价。

## 蓝牙使用

| 指令 | Q 模式下的作用 |
|---|---|
| Q | 从配置的初始位姿开始新一轮；会清零旧列表和本轮计数，请勿循环连发 |
| V | 查看当前状态、视觉链路、Q 收集计数、列表数量和卸货状态 |
| M 或 P | 输出按当前距离排序的目标列表；Q 下没有多目标路径 |
| S / X / 0 | 退出任务并停车，关闭自动解卡；普通停车保持前刷正转 |
| H | 停轮停刷并保持 HOLD；之后 K 恢复前刷，Q 重新开一轮 |
| A / C / D | 切换技术赛/对抗赛/调试模式，结束 Q 模式 |
| J | 原有手动解卡，正常结束后保留 Q 软件计数并重新等待视觉、补扫 |
| G | 原有舵机测试，会退出自动任务，不用作贪心模式入口 |

反馈示例（数值仅为示例）：

```text
MODE=GREEDY: DISTANCE ONLY, PICKUP ACTIONS=10 THEN UNLOAD
GREEDY COUNT=3/10 LIST=2 CURRENT=5 STATE=NAVIGATE ASSUMED=1
DIST RANK=1 ID=5 MM=480 C=1 X=1200 Y=900 AGE=80
DIST RANK=2 ID=8 MM=860 C=2 X=1700 Y=1100 AGE=600
GREEDY COLLECTED=4/10 ASSUMED=1
GREEDY EMPTY: RESCAN; KEEP PICKUP COUNT
GREEDY BATCH=10: RETURN TO UNLOAD
UNLOAD STARTED: GO TO LOWER-LEFT TARGET ZONE
UNLOAD COMPLETE
```

`COUNT` 是本轮完成的收集动作数；`LIST`/Q 下 `MAP` 是未收集且未过期的候选数；`CURRENT` 是正在接近或锁定的 ID。已锁定目标不一定仍是列表中的第一名。`AGE` 是距最后一次观测的毫秒数。Q 返回后保持 `COUNT=10/10`，直到重新开始任务。

## 动态列表和异常处理

- 使用固定 32 条记录，其中包括最多 10 个已收集位置；满容量时替换最久未观测的未收集项，保留已收集位置。没有动态内存分配。
- 未收集记录 20 秒未重新观测便失效。这允许旋转后暂时离开视野的物块仍可被选中，同时避免永久追逐旧坐标。
- 本轮已收集位置保留至下一次启动，避免同一物块反复进入计数。同色物块间距小于 120 mm、物块被推移或里程计漂移，仍可能造成误合并或重复识别，需要实测调整。
- 视觉失联超过 1.2 秒时停轮，清除未收集列表，保留本轮计数和已收集位置；新帧恢复后补扫。前刷持续正转。
- 解卡正常结束同样保留计数，清除可能已被推动的候选，要求新视觉帧后再补扫。解卡中断/HOLD 不自动恢复任务。
- 近距离目标匹配失败时停车等待，超时后沿用旋转恢复，丢弃失败候选，之后重新观察。
- 保留导航时超声/场地边界保护；末端对准与收集沿用原逻辑。没有新增障碍地图、A* 或后向距离传感器。

## 参数和输入输出

| 位置 | 参数或职责 |
|---|---|
| `Core/Inc/greedy_collection.h` | `GREEDY_BATCH_SIZE=10`、容量 32、TTL 20000 ms、重选间隔 300 ms、同色合并半径 120 mm |
| `Core/Src/greedy_collection.c` | 输入目标颜色/场地坐标/时间戳和当前位姿；输出按距离排序的 ID、最近目标、已收集动作数 |
| `Core/Src/main.c` | Q 入口、视觉坐标转换、每阶段车轮控制、10 次完成后的返仓入口、蓝牙距离列表 |
| `Core/Inc/mission_extension.h` | 场地 3000×2000 mm，起点默认 `(450,1000)`、航向 0；卸货准备点 `(650,200)`、倒车终点 `X=180`；均需符合实际场地 |
| 原 OpenMV 程序 | 继续输入图像、输出带校验的红黄目标帧；Q 使用扫描命令 `C,S,0` 持续观察全部颜色 |

距离列表要在转弯后仍有效、并且要返回卸货区，因此依然需要车轮编码器里程计。编码器方向、每圈计数、轮径/轮距、摄像头测距和起始位置需要标定。若要开始第二轮，先把车放回配置起始姿态再发 Q，因为 Q 会重置位姿和任务计数。

这里的 10 个沿用原工程的**900 ms 动作完成推定**，`ASSUMED=1` 用于说明没有入仓传感器确认。未收到有效视觉、仅识别到目标、接近中丢目标、收集中被停止或解卡打断，都不应加计数。计数仍不能证明物块真实进入仓体；前刷编码器反馈只判断刷子运动，不是物块计数器。

## 编译、验证和上车

导入包内 `collection_car_combat_v6_1` 工程，刷新工程、Clean、Build，确认 `Core/Src/greedy_collection.c` 被编译，再烧录生成的 ELF。Core 已是 CubeIDE 源码目录，不需要增加 CubeMX 外设或修改引脚。启动时蓝牙应包含 `FW=v6.1+GREEDY`。

软件验证命令：

```sh
make -C STM32F103VET6_collection_car_combat_v6.1/tests test
```

已通过宿主测试（真实 C 函数、模拟硬件）和 HAL 头文件下的 C 语法检查。新增测试覆盖距离排序随位姿改变、Q=0 单帧入列、合并/过期/时间回绕/容量、近距离锁定、视觉/解卡恢复、模式退出，以及连续 10 次状态机收集后一次返仓倒车舵机卸货。测试还记录加权规划器调用次数，Q 全过程为 0。未完成 ARM 链接构建或实车试验。

实车先确认 D 模式视觉链路已显示 `VISION OK`、左右转向和编码器方向正确，再测试 Q。观察 `V/M` 的距离、计数与实际物块对照；前刷会常转，停刷使用 H。测试用本轮数量可在 `GREEDY_BATCH_SIZE` 中修改后重新编译，正式版本默认 10。
