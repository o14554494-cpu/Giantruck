# v6：前刷持续收集，后舵机单独卸货

本文件是当前行为说明。旧 V5.3 文档中“上电前刷停止”“视觉失联停刷”“卸货反转刷子”的描述已被本次修改取代。

## 前刷独立运行

- 刷子对应第三电机：PB0/PB1 设置方向，PC8/TIM8_CH3 提供 PWM。
- 上电后配置引脚、启动 PWM 外设、检查启动返回值，然后执行 `motor3_forward(COLLECTOR_RUN_PWM)`。
- 默认 `COLLECTOR_RUN_PWM=500`，TIM8 周期为 1000 个计数，因此是 50% 占空比。
- 参数在 `Core/Src/main.c` 顶部，范围应为 0..1000。车轮的最低 PWM 映射及用户新增车轮启动补偿不作用于刷子。
- 启动后依靠定时器持续输出，不依赖主循环重复启动。自动任务和卸货不再读写刷子的 PWM 或方向。
- 删除 `motor3_reverse` 和 `motor3_stop` 及其任务调用，避免任务状态遗留停刷或反转动作。

| 状态或指令 | 前刷 | 车轮/后舵机 |
|---|---|---|
| 初始化完成，尚未发指令 | 正转 50% | 保持原待机行为 |
| 蓝牙 F/B/L/R | 持续正转 | 按原驾驶控制执行 |
| 蓝牙 S/X 或速度 0 | 持续正转 | 按原停车/任务重置逻辑执行 |
| 自动扫描、导航、收集 | 持续正转 | 按任务执行 |
| 等待视觉、视觉失联、对准丢目标 | 持续正转 | 保留车轮视觉停车保护 |
| 返仓、调整朝向、倒车入卸货区 | 持续正转 | 按原返仓轨迹执行 |
| EJECT 卸货 | 持续正转，不反转 | 后舵机按原路径往复扫动 |
| 卸货完成、下一轮、卸货超时故障 | 持续正转 | 按原任务状态处理 |

本版没有设置独立的蓝牙停刷指令；S/X 不关闭前刷，要完全停止前刷需切断其供电。

## 后舵机单独负责卸货

- 后舵机对应 PA8/TIM1_CH1，仍由 `Servo_StartEject` 与 `Servo_Update` 控制。
- 保留用户 v6 的舵机动作路径和 5 秒卸货阶段。
- `mission_extension.c` 的 EJECT 输出不再包含 `-700` 刷子反转指令，改为 0。
- `MissionDriveOutput_t.collector_pwm` 暂留以保持结构接口兼容，现为保留字段、始终为 0；主循环不再用它控制前刷。
- `Mission_UpdateIntegration` 只处理原有车轮指令和后舵机动作，不再在卸货开始、进行、结束时改变前刷。

## 蓝牙状态

V 返回的卸货状态行增加 `BRUSH=CONT PWM=500/1000`。它表示刷子的配置输出，不是传感器测得的转动反馈。

视觉失联消息改为：

```text
VISION LOST: WHEELS STOPPED, BRUSH CONTINUES
```

如果烧录后刷子仍不转，应在 PC8 检查 PWM、在 PB0/PB1 检查方向电平，以及检查驱动器使能、电源和刷子启动负载；不能从软件配置输出直接判定电机已物理转动。

## 验证范围

`make -C tests test` 通过。更新后的控制回归测试提取实际 main.c 函数，配合实际卸货/规划模块和模拟硬件，验证：

- 前刷启动后，在视觉丢失/恢复、目标丢失、所有收集状态中保持正转。
- 蓝牙 F/B/L/R/S/X/A/C/0/G 不写入前刷 PWM。
- 完整返仓卸货、下一轮和卸货超时故障均不改变前刷 PWM。
- EJECT 阶段调用后舵机更新，同时前刷方向保持正向；卸货输出不再请求反转。
- 相关固件 C 文件通过宿主 clang 语法检查。

这是软件决策与输出验证，尚未重新完成 ARM 固件构建或实车测试。请在 CubeIDE 重新编译后烧录。

用户 v6 中的车轮启动补偿、手动前进被避障接管等逻辑保持原样。回归测试的车轮输出断言已适配收到的 80% 启动补偿阶段，不代表此前发现的“200ms 后缺少周期退出”等问题已修复。
