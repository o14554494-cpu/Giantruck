# v5.3 控制修订（2026-09-02）

本次仅落实用户指定的三项修改，不改变视觉串口协议，不修改 OpenMV 脚本。
工程名保持不变，避免破坏 CubeIDE 工程配置。此包是控制源码，需重新构建烧录，不包含新编译的固件。

## 1. 卸货后恢复收集滚轮

- `Auto_StartScan` 先停稳，进入扫描后通过视觉有效性检查再正转滚轮。
- `AUTO_SCAN` 和 `AUTO_COLLECT` 显式输出 `COLLECTOR_RUN_PWM`，保证对抗赛下一轮和重新启动任务时均可恢复收集。
- 滚轮参数仍为 `main.c` 中的 `COLLECTOR_RUN_PWM=500`（原 0..1000 档位）。本次车轮 60% 下限不应用于收集滚轮或舵机。
- 上电不再直接启动滚轮，收到 A/C 并有有效视觉后才进入收集任务。

## 2. 视觉失联保护

- 保护范围：SCAN、PLAN、NAVIGATE、ALIGN、COLLECT、RECOVER、PATROL。
- 启动后未收到完整有效帧时，车轮与滚轮保持停止。
- 最近一帧超过 `AUTO_VISION_TIMEOUT_MS=1200` 毫秒：停止车轮和滚轮，清除当前目标、旧路线和未收集候选，保留已收集记录、仓内计数和里程计位置。
- 失联时每 `AUTO_VISION_RETRY_MS=500` 毫秒重新请求视觉扫描；不做盲目转圈恢复。
- 恢复有效帧后重新扫描，再规划，不续跑失联前的半次收集，也不把它直接算为成功。
- 收到新帧但其中没有当前对准目标：立即停止车轮与滚轮，然后按原有超时策略转入恢复。
- 有效的零目标帧是正常通信心跳，不等于失联。导航中的目标可暂时在视野之外，因此没有把每个空画面都当作断线。
- 避障控制不能覆盖失联停车输出。
- 手动驾驶和已经开始的里程计返仓/卸货不依赖视觉，仍保留原逻辑。比赛时钟没有暂停。

蓝牙反馈：

```text
VISION LOST: WHEELS AND COLLECTOR STOPPED
VISION RESTORED: RESCAN BEFORE COLLECTING
```

发送 `V` 的状态新增 `VHOLD=1/0`：1 为视觉失联停车等待，0 为未处于该等待状态。`AUTO` 在等待时可能仍显示原状态，判断是否等待应查看 `VHOLD`。

## 3. 车轮 PWM 下限 60%

配置位于 `Core/Inc/drive_pwm.h`：

```c
#define MOTOR_MIN_DRIVE_PWM_PERCENT 60
```

原有速度参数现在表示逻辑档位，不是最终 PWM。非零档位幅值 1..100 线性映射到物理占空比 60..100（取整），符号控制正反转；0 始终关闭输出。映射在最终车轮输出入口执行一次，因此手动、扫描、导航、恢复、避障和倒车卸货均受覆盖。

| 原逻辑指令 | 新车轮 PWM |
|---|---:|
| 停车 0 | 0% |
| 最小非零档 1 | 60% |
| 扫描 18 | 67% |
| 末端接近/倒车 20 | 68% |
| 导航基准 35 | 74% |
| 默认手动 40 | 76% |
| 最大 100 | 100% |

差速计算后的左右轮档位可能与表中基准不同。PWM 状态字段现在报告映射后的实际指令。定时器比较值按 ARR+1 计算，避免请求 60% 而因计算误差低于 60%。

这不是测速闭环：`MOTOR_CLOSED_LOOP_ENABLE` 仍为 0。非零档位都有至少 60%，低速能力取决于电机、负载、电源与减速机构；不能保证原来的行驶速度或转弯半径不变。若以后打开 PID，必须针对补偿后的输出重新整定。

## 验证

在工程目录执行（需要本机 C 编译器、Python 3）：

```sh
make -C tests test
```

- 原有协议、地图、路径、卸货与对抗模块测试通过。
- 新增 `tests/control_regression.py`，从当前 main.c 提取实际控制函数，链接实际地图/规划/任务模块，使用虚拟 GPIO、定时器和时钟运行，避免复制一份控制逻辑进行自测。
- 覆盖非零 PWM 下限、方向、单调映射、限幅、停止和定时器比较值；各收集状态失联；初始无帧；恢复后重扫；对准空帧；时钟回绕；完整卸货到下一轮滚轮启动；避障输出不得覆盖失联停车。
- 相关 C 文件通过宿主 clang 语法检查。没有完成 ARM 固件链接或实机运行验证。

## 实机验证顺序与剩余风险

1. 架空驱动轮，确保滚轮和舱门活动范围内无人/异物；准备独立断电手段。
2. OpenMV 未启动时发送 A/C：应保持停车、滚轮不转；连接后应报告恢复并扫描。
3. 扫描/导航中断开视觉发送：主循环正常运行时，超过 1.2 秒应停止；恢复应重新扫描。
4. 对准中让目标消失：应立即停止原有前进/转向输出。
5. 用 V 检查 PWM 与 VHOLD；验证正反转以及停车 0 输出。
6. 完成一次卸货，确认下一轮扫描滚轮重新正转，之后再做地面低风险测试并重新标定。

本次未处理上一轮审查中的其他问题：超声波 DWT 计时回绕可能卡主循环、卸货期间 S/G 控制权冲突及 X 未统一停止滚轮、G 扫摆缺少更新、蓝牙单字符覆盖、视觉曝光接口/跨色误删等。主循环卡死时，本次软件视觉保护也无法运行，因此它不是独立硬件急停。不要把本次通过的软件测试视为上述问题已经消除。
