# STM32F103VET6 · 对抗赛 v8.4.3

这是 Giantruck 对抗挑战赛的 STM32CubeIDE 固件工程。工程在上电后先建立比赛计时和 IMU 参考，但不会自动开车；操作者通过蓝牙发送 `C` 或 `Q` 才开始/恢复 Greedy。代码以“短周期可恢复、最后一分钟确定性卸货”为目标，适用于两车同时在 3 m × 2 m 场地内争夺物块的五分钟比赛。

## 1. 工程边界

- 本目录是 `combat-v8.4.3` 分支的有效烧录工程，入口为 `Core/Src/main.c`。
- `Core/Src/main.c` 不能删除：它负责 HAL 初始化、主循环、蓝牙命令分发和全部状态机。
- 仓库根目录的 `STM32F103VET6_collection_car_combat_v6.1/` 是历史存档，里面的旧技术赛/Greedy 逻辑不参与本工程编译，也不能与本目录混用。
- OpenMV 与 STM32 通过视觉协议传递目标和黑区信息；STM32 负责状态机、运动控制、计时、故障恢复和舵机卸货。

## 2. 上电、计时与启动

上电后执行以下并行准备：

1. 初始化车轮、前刷、舵机、UART、编码器、超声和 JY901S；
2. 启动 300 s 比赛计时器；
3. 车体静止采集连续 10 帧 IMU 航向，锁定 `START_RAW` 作为本场初始 `0°`；
4. 在 `COMBAT_STANDBY` 待机，车轮、前刷和舵机不执行自动动作；
5. 收到 `C` 或 `Q` 后，才进入 Greedy，启动前刷反馈和目标扫描。

计时起点是 STM32 上电时刻。蓝牙人工操作、`S` 停车、反复发送 `C/Q` 或前刷解卡都不会暂停计时；若需要重新开始一场比赛，应发送 `X` 后再次发送 `C/Q`，或者直接复位 STM32。比赛剩余最后 60 s（从 240 s 起）时，最终卸货流程会抢占普通收集；到 300 s 所有执行器强制停止。

## 3. Greedy 收集状态机

```text
COMBAT_STANDBY
      │ C/Q
      ▼
SCAN ──发现目标──> NAVIGATE → FINAL_ALIGN → COLLECT
  │                                      │
  └─无目标且 <240 s──> PATROL <─────────┘
                                      │拾取/解卡后
                                      └──刷新短期 IMU → SCAN

任意自动状态 ── elapsed ≥240 s ──> 最终黑区返回/卸货 → COMPLETE
```

### 扫描

- 每轮 6 个 60° 步进，共约 360°；每段转到目标角后短暂停车并观察，避免连续高速旋转漏检。
- 视觉帧中的目标在相机坐标中处理，不把一次观测简单累加成重复物块；当前策略锁定一个可靠目标，完成后再重扫。
- 扫描转向由双轮差速和 IMU 转角控制共同约束；转向或编码器故障会报告并暂停自动，而不是无限盲转。

### 跟随与收集

- `NAVIGATE` 根据目标横向偏差施加左右轮差速，让物块进入前刷中心；`FINAL_ALIGN` 使用较低速度完成近距离对准。
- 目标进入视觉近距离盲区后，`COLLECT` 继续按编码器位移前进额外距离，避免“目标刚消失就误判已收集”。
- 前刷是独立执行器，进入 Greedy 后持续正转；后方舵机只在卸货状态动作，不承担收集任务。
- 每次收集动作结束后停车，并在安全扫描边界刷新短期 IMU 参考，再开始下一轮扫描。

### 空扫描后的局部巡航

比赛未到 240 s 且完整扫描无目标时，进入 `PATROL`：沿当前航向直行约 1000 mm，或达到 9 s 安全上限即停车重新扫描。巡航过程中仍处理新鲜视觉目标，发现目标就立即回到 `NAVIGATE`。该策略不依赖累计场地坐标，能降低轮胎打滑造成的全局定位误差。

## 4. 双参考 IMU 与严格帧过滤

- **初始参考 `START_RAW`**：上电静止 10 帧锁定，只用于最终返回/卸货的初始方向，整场不被人工接管、拾取或解卡覆盖。
- **短期参考 `LOCAL_RAW`**：用于下一段直线和倒车的航向保持。拾取/解卡后刷新；连续运行时每 30 s 在下一个安全扫描停车边界刷新 6 帧，不需要把车转回初始方向。
- IMU 接收器拒绝过期帧、单帧大跳变、异常角速度和与编码器航向明显不一致的恢复帧；恢复需要多帧连续一致。失败时保留旧参考，不把低可信度数据写入控制器。
- `IMU_DUAL` 诊断中，`START_RAW` 应在整场保持不变，`LOCAL_RAW` 只会在成功刷新后变化。

这套机制能减小震动和短期偏置对直线的影响，但不能单独修复磁场干扰、IMU 松动或编码器丢脉冲造成的真实漂移。

## 5. 卡住、解卡和碰撞恢复

### 前刷自动解卡

进入 Greedy 后启动前刷监测，给电机 1 s 启动宽限；随后低转速低于约 5 rpm 持续约 600 ms，或启用的脉冲/电流条件触发堵转：

```text
停止车轮/前刷 → 换向缓冲 → 前刷反转约两圈并让车体后退
→ 停顿 → 恢复前刷正转 → 前进约50 mm → 重新扫描
```

自动最多尝试 5 次，仍未恢复进入 `JAM_HOLD`。检查刷子、编码器方向和接线后发送 `K` 恢复，再发送 `C/Q` 继续；`J` 可手动触发一次解卡。

### 车轮碰撞恢复

仅在 240 s 前的正向跟随、收集和巡航阶段启用。程序分别累计左右轮 3 s 的前进位移；若两个车轮在窗口内都小于 10 mm，认为与墙/对手卡死：

```text
停车约150 ms → 双轮后退约50 mm → 左轮后退、右轮前进，逆时针约110°
→ 清除旧目标 → 回到 Greedy 扫描
```

后退和转向分别有安全时限，编码器达不到目标会暂停自动并提示检查。该方法能发现“电机也没有转”的卡死；若车轮贴墙空转、编码器仍在增加，现有硬件无法仅凭位移识别纯打滑。

## 6. 最终黑区返回与卸货

到 240 s 由计时器强制进入，普通 Greedy、巡航、人工车轮控制和刷子解卡均让位于此流程：

```text
对齐 START_RAW 初始方向
  → IMU PID 逆时针90°
  → 保持航向倒车，后方超声连续3个新鲜样本 ≤180 mm
  → IMU PID 再逆时针90°
  → 低速直行搜索黑区
       黑色占比 ≥3% 且连续3帧：开始黑区跟随
       黑色占比 ≥40%且连续3帧：确认到达黑区
  → 编码器后退80 mm，重新对齐 START_RAW
  → IMU PID 逆时针30°
  → 倒车进入卸货位
       后方超声 ≤120 mm，或编码器后退 ≥300 mm，或10 s兜底
  → 舵机开舱门（内转90°、外转180°）并前后小位移抖动
  → 保持舱门终点，等待比赛结束
```

后方超声安装在车尾，因此只用于倒车距离判定；黑区识别来自 OpenMV。舵机动作由 `servo.c` 的一次性序列控制，卸货阶段不会重新启动收集刷。

## 7. 蓝牙命令

蓝牙使用 ASCII 单字符，建议每次发送一个字符并等待反馈：

| 命令 | 作用 | 备注 |
| --- | --- | --- |
| `C` / `Q` | 启动/恢复 Greedy | 不重置比赛计时 |
| `F` / `B` / `L` / `R` | 人工运动 | 暂停自动车轮控制，计时继续 |
| `S` | 仅停轮 | 前刷当前输出保持不变 |
| `Z` | 停止/恢复前刷 | 卸货占用时拒绝 |
| `V` | 状态诊断 | 含计时、状态、视觉、IMU、编码器、超声和故障 |
| `D` | 黑区返回/卸货台架测试 | 不代替正式计时触发 |
| `U` | 后方超声监视 | 查看距离和新鲜度 |
| `G` | 舵机台架测试 | 再按一次停止并回中 |
| `J` / `K` | 手动解卡 / 恢复 `JAM_HOLD` | 处理实物故障后使用 |
| `H/N/T/E/O` | 前刷标定、监测启停辅助 | 详见刷子指南 |
| `0` | 停止自动动作 | 不清除比赛时钟 |
| `X` | 终止并清空当前任务 | 后续 `C/Q` 建立新计时 |
| `A` | 禁用 | 防止旧技术赛逻辑混入 |

常见状态：`COMBAT_STANDBY`、`IMU_ZERO_WAIT`、`SCAN`、`NAVIGATE`、`FINAL_ALIGN`、`COLLECT`、`PATROL`、`UNLOAD_*`、`JAM_HOLD`、`COMPLETE`。

## 8. 文件与模块职责

| 路径 | 职责 |
| --- | --- |
| `Core/Src/main.c` | 主循环、状态机、蓝牙命令、运动和比赛时序总入口 |
| `Core/Src/greedy_local.c` / `greedy_collection.c` | 单目标跟随、扫描和收集决策 |
| `Core/Src/imu_navigation.c` / `jy901.c` | IMU 协议解析、严格帧过滤、航向控制与参考管理 |
| `Core/Src/vision_protocol.c` | OpenMV 帧解析、目标/黑区数据新鲜度管理 |
| `Core/Src/combat_strategy.c` | 对抗赛时间窗、巡航与最终阶段判定 |
| `Core/Src/coverage_path.c` / `path_planner.c` | 保留的路径模块；本版 Greedy 主流程不依赖全局最短路线 |
| `Core/Src/brush_feedback*.c` | 前刷编码器/电流反馈和自动解卡 |
| `Core/Src/servo.c` | 后舱门 PWM、开门往复和卸货序列 |
| `OpenMV/` | 视觉脚本与启动脚本，输出目标和黑色区域协议帧 |
| `tests/` | 主机端控制/反馈回归测试 |

## 9. 接口与烧录

| 模块 | STM32 接口 |
| --- | --- |
| OpenMV | UART4，PC10/PC11，115200 8N1，TX/RX 交叉并共地 |
| 蓝牙 | USART3，PB10/PB11，115200 8N1，ASCII |
| JY901S | USART1：PA10 接 IMU TX，PA9 接 IMU RX，9600 |
| 车轮/前刷编码器、后方超声、舵机 | 沿用 v7.6.2 工程的定时器、EXTI、PWM和GPIO配置 |

在 STM32CubeIDE 中导入本目录的 `.project`，执行 `Clean Project` → `Build Project`，确认生成的 ELF 来自本目录的 `Debug/`，再用 ST-Link 烧录。主机测试：

```sh
make -C tests test
```

烧录后建议按 `V`、`U`、`G`、`I` 的顺序做通信/超声/舵机/IMU 台架检查，再发送 `C` 或 `Q` 做低速实车测试。
