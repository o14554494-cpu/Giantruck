# v7.6.2 IMU 90°/180° 卸货转向修订

基线：`STM32F103VET6_collection_car_combat_v7.6.2_black_backup50`

## 本版唯一功能变更

卸货流程中，90°和180°转向均改为使用 JY901S 航向的连续 PID 闭环，取消旧的“接近目标后低速脉冲/滑行微调”以及 90°末段提前放行：

```text
后墙确认 → IMU PID 旋转 90° → 沿墙找黑区
黑色区域 40% 确认 → 后退 50 mm
             → IMU PID 旋转 180° → 原有倒车/超声判断 → 原有舵机卸货
```

## 控制参数与实现

- 新增仅用于 90°/180°的 `BLACK_TURN_PID_KP=24.0f`；原有 `BLACK_HEADING_PID_KP=18.0f`（启动 0°和碰撞恢复等其他对准保持不变）。`KI=0.30f`、`KD=0.80f`、输出上限 20% 保持不变；提高比例作用，同时限制最大转向速度，避免过冲。
- 90°步骤必须由 `BlackUnload_Align()` 到达普通 `BLACK_HEADING_TOLERANCE_RAD`（±2°）并稳定 500 ms 后才进入前进找黑区，不再使用旧的 ±12°可用区。
- 180°步骤在 50 mm 预倒车完成且 IMU 数据新鲜时，锁存当前航向并生成“当前航向 + 180°”目标；同一 `BlackUnload_Align()` PID 持续驱动到 ±2°并稳定确认。
- 180°的 `TURN_MRAD`遥测改为由 IMU 起始/当前航向计算；到位反馈改为 `IMU TURN VERIFIED=...`。
- IMU 失联时车轮停止并等待恢复；超过原有 180°超时则安全停车。50 mm预倒车、编码器里程、视觉阈值、后续倒车/超声、舵机和其他模式均保持不变。

## 删除的旧微调内容

- 删除 90°末段 ±12°提前接受逻辑。
- 删除 `BlackUnload_Align()` 的 50 ms/200 ms 最小 PWM 脉冲滑行逻辑。
- 删除 180°编码器角度闭环及 60 ms/200 ms 微调逻辑；编码器仍用于车辆里程和 50 mm/后续倒车距离。

## 验证

- `make -C tests clean all`：全部主机控制、刷子反馈、JY901、采样回归通过，包含 90°/180°连续 IMU PID、过冲纠偏和 50 mm预倒车流程。
- `clang -fsyntax-only ... Core/Src/main.c`：通过 STM32 HAL 头文件语法检查。
- `python3 -m py_compile OpenMV/main.py`：通过；OpenMV文件未修改。

尚未进行 ARM 链接、实际烧录和实车 IMU 标定。首次实车测试应先确认 IMU 安装方向、`IMU_NAV_YAW_SIGN` 和 24% Kp 下的实际转角/过冲，再按需要微调 Kp 或输出上限。

## 追加修订：后墙阈值与卸货超时余量

- 对齐初始航向后，`AUTO_UNLOAD_REVERSE_WALL` 的后方超声停车阈值由 `150 mm` 改为 `200 mm`，仍要求连续 3 个新鲜采样确认；蓝牙提示同步改为 `REAR WALL 200MM CONFIRMED`。
- 为适应低速倒车、IMU稳定确认、超声采样和机械启动延迟，适度放宽自动卸货阶段的有限超时：
  - 初始0°/90°对齐：`8 s → 12 s`
  - 倒车靠后墙：`12 s → 20 s`
  - 沿墙寻找黑区：`25 s → 35 s`
  - 180° IMU转向：`12 s → 16 s`
  - 180°后进入卸货区倒车：`5 s → 8 s`
  - 180°前50 mm预倒车：`2.5 s → 4 s`
  - 黑区视觉跟随：`15 s → 20 s`
- `MOTOR_COMMAND_TIMEOUT_MS`、`AUTO_VISION_TIMEOUT_MS`和超声/IMU数据新鲜度判断未放宽。它们属于通信或传感器失联保护，不能用延时掩盖编码器、IMU、超声接线或机械卡滞问题。

### 常见 TIMEOUT 原因

1. **编码器计数没有增长或符号错误**：50 mm预倒车、转后250 mm倒车会一直达不到里程目标。
2. **IMU数据过期或未达到稳定帧数**：0°、90°、180°对齐会停轮等待，最终触发对齐超时。
3. **后方超声无回波/读数偏大**：靠墙阶段永远无法连续确认 `<=200 mm`。
4. **视觉数据过期或黑区确认不足**：沿墙搜索/黑区跟随会停车等待，视觉有效时间超过阶段上限后超时。
5. **电机处于死区、负载过大或车轮打滑**：指令已发出但实际位移/转角不足。

因此本次只增加自动卸货流程的时间余量，仍保留有限上限；如果延长后仍频繁超时，应根据蓝牙中具体的 `... TIMEOUT: CHECK ...` 提示检查对应反馈，而不是继续无限加长时间。
