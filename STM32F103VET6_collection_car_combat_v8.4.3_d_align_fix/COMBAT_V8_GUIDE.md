# v8.0 对抗赛工程说明

## 1. 上电与比赛时间

- 上电立即启动独立的 300 秒比赛时钟，不等待蓝牙命令。
- 同时采集连续 10 帧稳定 JY901S 航向，保存为整场比赛的初始 0°参考。
- 采集期间车轮和前刷停止；若发送 `F/B/L/R`，程序会拒绝运动，避免把移动中的航向误存为零点。
- IMU 初始化完成后仍保持 `COMBAT_STANDBY`，不会自动进入 Greedy。
- 蓝牙 `C`、`Q` 均用于启动或恢复 Greedy，且不会重置比赛计时。
- 240 秒进入最终返回/卸货，300 秒无条件关闭车轮、前刷和舵机动作。

注意：本版本把 STM32 上电时刻定义为比赛计时起点。如果裁判计时晚于上电，请在正式开始时重新复位 STM32，再保持车体静止完成零点采集并发送 `C/Q`。

## 2. Greedy 收集流程

1. 前刷启动，并启用刷子堵转监测。
2. 小车执行 6×60°分段扫描；每一段转完停车观察。
3. 发现物块后锁定当前目标，按视觉横向偏差差速对准并向前跟随。
4. 物块进入视觉盲区后继续按编码器前进额外距离，完成一次拾取动作。
5. 停车刷新短期 IMU 航向，再重新扫描。
6. 完整扫描仍无物块且比赛未到 240 秒时，不提前卸货，而是直行巡航 1000 mm 后再次扫描。巡航期间仍实时接收物块和蓝墙信息；发现目标立即切回跟随。

巡航不依赖累计场地坐标，避免长时间打滑后按错误坐标前往固定点。单次巡航还有 9 秒安全上限；编码器达到 1000 mm 或时间到，都会停车重扫。

## 3. IMU 双参考机制

- **初始参考**：上电的 10 帧静止采样，只用于保留比赛初始方向和最终黑区返回，不因人工接管或解卡而被覆盖。
- **短期参考**：车辆停在扫描边界时采集 6 帧，用于直线航向保持；拾取或解卡后会刷新，连续运行时每 30 秒也会在下一个安全停车扫描边界刷新。

短期刷新不要求把车转回 0°，也不会修改初始 0°。没有外部绝对地标时，程序无法仅靠“定时写零”修复磁航向的绝对漂移；因此这里刷新的是当前直线控制参考，而不是伪造新的比赛初始方向。

## 4. 碰撞和卡住处理

### 前刷卡住

- 上电待机时前刷关闭；进入 Greedy 后自动启用监测。
- 启动宽限为 1 秒，之后低于 5 rpm 持续 600 ms（或无脉冲/校准后的过流）判为堵转。
- 自动流程：停车和停刷 → 延时换向 → 前刷反转约两圈（未标定 CPR 时按时间反转）并让车后退 → 停顿 → 前刷恢复正转 → 小车前进 50 mm → 回到重新扫描。
- 最多自动尝试 5 次；仍失败进入 `JAM_HOLD`，需检查实物后发 `K` 恢复，再发 `C/Q` 继续。

### 车轮卡住/与对手相撞

- 仅在比赛前 240 秒的跟随、最终对准、收集和巡航正向行驶阶段启用。
- 左、右轮分别建立 3 秒编码器窗口；若两个车轮在该窗口内各自前进行程都小于 10 mm，判定碰撞卡死。
- 自动执行：停车 150 ms → 双轮后退 50 mm → 左轮后退、右轮前进，原地逆时针转 110° → 清除旧目标并重新进入 Greedy 扫描。
- 后退最多允许 4 秒，转向最多允许 6 秒；编码器未达到目标会暂停自动并提示检查，避免无限盲动。
- OpenMV `$W` 蓝墙包仍可在 `V` 中查看，但不再触发或中止运动。
- 注意：此方法检测的是“编码器也没有转”。如果车轮贴墙空转，编码器仍会累计距离，因此仅靠现有硬件不能保证识别这类打滑碰撞。

## 5. 240 秒最终卸货

240 秒触发优先级高于待机、人工模式、普通扫描、巡航以及正在执行的前刷解卡/`JAM_HOLD`。程序先安全关闭前刷并取消解卡，再进入最终返回，防止刷子故障拖过最后一分钟。

保留的 v7.6.2 黑区流程为：

1. IMU 对齐上电初始 0°；
2. IMU PID 逆时针转 90°；
3. 保持航向倒车，后方超声连续 3 个新鲜采样 ≤180 mm；
4. 再用 IMU PID 逆时针转 90°；
5. 慢速直行寻找黑色区域，黑色占比连续 3 帧 ≥3% 后视觉接管方向；
6. 黑色占比连续 3 帧 ≥40% 后，编码器后退 80 mm；
7. 对齐初始方向，再双轮逆时针转 30°；
8. 倒车进入卸货区；后方超声 ≤120 mm、双轮编码器 ≥300 mm、或倒车达到 10 秒，任一条件成立即开始卸货；
9. 后舵机执行开舱门动作，小车前后抖动卸货；完成后不再恢复收集，等待 300 秒硬停止。

## 6. 蓝牙命令

| 命令 | 功能 |
|---|---|
| `C` / `Q` | 启动或恢复对抗赛 Greedy；不重置比赛时钟 |
| `F` / `B` / `L` / `R` | 人工前进、后退、左转、右转；暂停自动但计时继续 |
| `S` | 仅停止车轮并暂停自动流程；前刷输出保持不变，比赛计时继续 |
| `Z` | 单独切换前刷停止/正转；车轮及当前自动状态保持不变（卸货占用前刷时拒绝） |
| `V` | 输出车轮、视觉、Greedy、IMU双参考、黑区、堵转、比赛耗时等状态 |
| `D` | 台架调试：直接进入最终黑区返回/卸货流程；计时继续 |
| `U` | 后方超声实时监视模式 |
| `G` | 后舱门舵机台架测试，再按一次停止并回中位 |
| `J` | 手动启动一次前刷解卡流程 |
| `K` | 实物故障排除后，从 `JAM_HOLD` 恢复前刷 |
| `H/N/T/E/O` | 前刷编码器标定、启用/停用监测相关命令 |
| `0` | 停止自动动作，保留当前比赛时钟 |
| `X` | 终止并清空当前比赛；之后发 `C/Q` 会建立新的 300 秒计时 |
| `A` | 已禁用，避免旧技术赛/全局规划状态与对抗赛 Greedy 冲突 |

## 7. 关键状态反馈

- `COMBAT_STANDBY`：比赛时钟运行，等待 `C/Q`。
- `IMU_ZERO_WAIT`：正在采集初始 10 帧，必须保持静止。
- `SCAN`：6×60°寻找物块。
- `NAVIGATE / FINAL_ALIGN / COLLECT`：跟随、对准、盲区补偿拾取。
- `PATROL`：空扫描后的 1000 mm 局部巡航。
- `UNLOAD_*`：最终黑区返回及卸货子状态。
- `JAM_HOLD`：前刷自动解卡用尽或编码器方向/线路异常。
- `COMPLETE`：卸货完成等待终场，或已到 300 秒。

`V` 中的 `COMBAT ELAPSED=.../300000` 是从 STM32 上电开始的比赛毫秒数，`AUTO_EN` 表示自动控制是否拥有车轮，`FINAL_RETURN` 表示是否已进入最后一分钟卸货流程。

## 8. 通信与烧录

- OpenMV ↔ STM32：UART4，交叉连接 TX/RX并共地；视觉脚本位于 `OpenMV/visual_latest_20260908.py`（`OpenMV/main.py` 同步保留启动脚本）。
- 蓝牙 ↔ STM32：USART3，ASCII 命令。
- JY901S ↔ STM32：USART1，PA10 接 IMU TX，PA9 接 IMU RX，9600 baud。
- 后方超声、车轮编码器、前刷编码器及舵机引脚保持 v7.6.2 工程原配置，没有在本次对抗赛改造中重新分配。

在 STM32CubeIDE 导入本目录中的 `.project`，执行 `Project > Clean` 和 `Build Project` 后通过 ST-Link 烧录。主机回归测试命令为 `make -C tests test`。
