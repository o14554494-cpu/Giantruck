# Giantruck · 对抗赛固件

本分支为 `combat-v8.4.3`，面向五分钟对抗挑战赛。代码的实际入口和 CubeIDE 工程位于 [`STM32F103VET6_collection_car_combat_v8.4.3_d_align_fix/`](STM32F103VET6_collection_car_combat_v8.4.3_d_align_fix/)，该目录是本分支的唯一有效工程；其中的 [`README.md`](STM32F103VET6_collection_car_combat_v8.4.3_d_align_fix/README.md) 和 [`COMBAT_V8_GUIDE.md`](STM32F103VET6_collection_car_combat_v8.4.3_d_align_fix/COMBAT_V8_GUIDE.md) 记录了完整参数与调试方法。

> STM32 工程中的 `Core/Src/main.c` 是 HAL 启动入口，必须保留。仓库中的 `STM32F103VET6_collection_car_combat_v6.1/` 仅作为历史代码和旧说明存档，不应再导入或烧录。

## 一句话流程

```text
上电启动比赛计时与 IMU 初始采样
  → COMBAT_STANDBY 等待蓝牙 C/Q
  → 6×60°分段扫描，锁定一个目标并跟随收集
  → 拾取/解卡后刷新短期 IMU，继续扫描
  → 空扫描则在比赛前 240 s 做局部巡航再扫描
  → 240 s 进入黑区返回和卸货
  → 300 s 关闭车轮、前刷和舵机
```

## 比赛模式与时间

- 比赛总时长为 **300 s**。计时器在 STM32 上电时启动，人工接管、发送 `S` 或重复发送 `C/Q` 都不会暂停或重置计时。
- 上电同时进行连续 10 帧静止 IMU 航向采样，保存本场比赛的初始 `0°`；采样期间车轮和前刷保持安全状态。
- IMU 就绪后仍保持待机，收到蓝牙 `C` 或 `Q` 才启动/恢复 Greedy。若裁判计时与上电不同步，应在比赛开始前重新复位 STM32。
- 到 **240 s** 时最终卸货优先级最高；到 **300 s** 无条件停止执行器。

## Greedy 收集逻辑

Greedy 不使用全场坐标最短路线，而是“扫描—锁定一个—跟随—验证—重扫”的滚动策略：

1. 前刷独立持续正转，视觉执行 6 次、每次约 60°的扫描，每段结束后短暂停车观察。
2. 发现目标后锁定当前目标，按 OpenMV 返回的横向偏差进行差速对准，向目标前进。
3. 目标进入近距离盲区后，继续按编码器前进额外距离，完成一次拾取动作；成功后停车并刷新短期 IMU参考。
4. 整圈扫描没有目标且尚未到 240 s 时，进入局部巡航：直行约 1000 mm 或最多 9 s，途中若重新看到目标立即回到跟随，否则停车重扫。该巡航不依赖累计场地坐标，降低打滑造成的定位失效。

## 卡住与碰撞恢复

- **前刷堵转**：启动宽限 1 s 后，低转速/无脉冲持续约 600 ms 触发；程序停轮停刷、反转约两圈并后退，恢复正转后前进约 50 mm，再回到扫描。自动最多尝试 5 次，仍失败进入 `JAM_HOLD`，排除实物故障后发 `K` 恢复。
- **车轮碰撞**：比赛前 240 s 的跟随、收集和巡航正向行驶中，若左右轮在 3 s 窗口内各自前进都不足 10 mm，判为碰撞卡死；程序停车、后退约 50 mm，再以双轮差速逆时针转 110°，清除旧目标并重新扫描。
- 碰撞判断依赖编码器位移；若车轮贴墙空转而编码器仍计数，现有硬件无法可靠识别这种纯打滑情形。OpenMV 的蓝墙包只用于诊断，不直接触发避障。

## 240 s 最终黑区卸货

```text
对齐上电初始 IMU 方向
  → IMU PID 逆时针 90°
  → 保持航向倒车，后方超声连续 3 个新鲜采样 ≤180 mm
  → IMU PID 再逆时针 90°
  → 慢速直行寻找黑区（黑色占比 ≥3%，连续 3 帧）
  → 黑色占比 ≥40%，连续 3 帧
  → 编码器后退 80 mm并重新对齐初始方向
  → IMU PID 逆时针 30°
  → 倒车进入卸货位置
  → 后方超声 ≤120 mm、倒车编码器 ≥300 mm或 10 s 兜底
  → MG995 舵机开舱门并抖动车体卸货
```

卸货完成后不再恢复收集，等待 300 s 终场停止。黑色检测来自 OpenMV；超声安装在车体后方，因此只用于倒车距离判定。

## 蓝牙命令速查

| 命令 | 作用 |
| --- | --- |
| `C` / `Q` | 启动或恢复对抗赛 Greedy，不重置比赛时钟 |
| `F` / `B` / `L` / `R` | 人工前进、后退、左转、右转；自动暂停但计时继续 |
| `S` | 停止车轮并暂停自动，保持前刷当前输出 |
| `Z` | 独立切换前刷停止/正转 |
| `V` | 输出比赛计时、状态、视觉、编码器、IMU、超声和故障信息 |
| `D` | 台架直接测试黑区返回/卸货流程 |
| `U` | 后方超声监视 |
| `G` | 舵机开舱门台架测试，再按一次停止/回中 |
| `J` / `K` | 手动解卡 / 从 `JAM_HOLD` 恢复 |
| `H/N/T/E/O` | 前刷编码器标定及监测启停辅助命令 |
| `0` | 停止自动动作，保留比赛计时 |
| `X` | 终止并清空本场任务；之后 `C/Q` 才会建立新计时 |
| `A` | 已禁用，避免旧技术赛路径规划与对抗赛逻辑冲突 |

## 状态反馈

常见状态包括 `COMBAT_STANDBY`（等待启动）、`IMU_ZERO_WAIT`（采样初始零点）、`SCAN`、`NAVIGATE/FINAL_ALIGN/COLLECT`、`PATROL`、`UNLOAD_*`、`JAM_HOLD` 和 `COMPLETE`。发送 `V` 可查看 `COMBAT ELAPSED=.../300000`、`AUTO_EN`、`FINAL_RETURN`、`IMU_DUAL`、`RAW/MAP/AGE` 等诊断字段。

## 软硬件接口

| 模块 | 接口/配置 |
| --- | --- |
| OpenMV | UART4，PC10/PC11，115200 8N1；脚本在 `OpenMV/` |
| 蓝牙 | USART3，PB10/PB11，115200 8N1，ASCII |
| JY901S | USART1，PA10 ← TX、PA9 → RX，9600 |
| 车轮/前刷编码器 | 沿用 v7.6.2 工程接线和定时器/EXTI配置 |
| 后方超声 | 沿用 v7.6.2 配置，用于倒车停止判定 |
| 舵机 | 沿用 v7.6.2 的 TIM1 PWM 配置 |

## 编译、烧录与测试

1. 在 STM32CubeIDE 导入本目录中的 `.project`。
2. 执行 `Project → Clean Project`，再执行 `Build Project`。
3. 检查生成的 ELF 确实来自 `STM32F103VET6_collection_car_combat_v8.4.3_d_align_fix/Debug/`，再通过 ST-Link 烧录。
4. 主机回归测试：

   ```sh
   make -C STM32F103VET6_collection_car_combat_v8.4.3_d_align_fix/tests test
   ```

实车测试前先用 `V/U/G/I` 分别确认通信、后方距离、舵机和 IMU，再进行低速 Greedy 测试。仓库不提交 `Debug/`、`Release/` 或预编译固件。
